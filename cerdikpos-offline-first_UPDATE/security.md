# CerdikPOS — Keamanan dan bukti penerimaan

Status: rancangan kontrol hasil validasi 1.3, revisi offline-first, backend TypeScript, autentikasi dan VPN, menunggu persetujuan Phase 1. Bukan laporan vulnerability, hasil pentest, atau bukti implementasi. Hak peran: [requirement.md](requirement.md); endpoint: [stack.md](stack.md); persistensi: [database.md](database.md).

## Aset dan batas kepercayaan

Lindungi transaksi, kas, bukti pemeriksaan QRIS, saldo dan histori stok, sesi meja, nota fisik, identitas petugas, ekspor dan backup. Pemisah utama: perangkat kasir vs server, jaringan publik/LAN biasa vs jalur privat NetBird seluruh peran, aplikasi vs PostgreSQL, nota fisik vs input digital. Keanggotaan VPN, alamat yang diklaim klien, tombol tersembunyi, atau kepemilikan nomor nota bukan bukti kewenangan.

## Stack keamanan minimum

| Kebutuhan | Pilihan |
|---|---|
| Login dan sesi | Better Auth + PostgreSQL, username/password |
| Hash password | scrypt bawaan Better Auth |
| Izin | Pemeriksaan peran kasir/direktur di server, tanpa framework tambahan |
| Validasi input | Zod pada frontend dan backend Fastify |
| Proteksi request | HTTPS, secure cookie, pemeriksaan origin/CSRF, rate limiting |
| Integritas database | Query berparameter, constraints, transaksi atomik, idempotensi |
| Jaringan dan perangkat | NetBird, firewall dan registrasi perangkat sesuai rancangan |
| Audit dan backup | PostgreSQL, log terstruktur, backup terenkripsi dan uji restore |
| Pengujian | Test integrasi/API dan alur akses; gunakan runner yang sudah dipilih proyek |

Tidak menambahkan MFA/TOTP, OTP email, SSO/OAuth, Keycloak, Redis, WAF, SIEM, atau framework RBAC. Tidak perlu layanan eksternal untuk login. Gunakan fitur bawaan framework/library sebelum menambah dependency. OWASP ASVS dapat menjadi referensi checklist, bukan target sertifikasi atau kewajiban memasang tool tambahan.

## Akses jaringan, akun, dan sesi

- **Better Auth** sebagai library autentikasi self-hosted terintegrasi langsung dalam backend TypeScript + Fastify pada Node.js LTS di PC lokal, menggunakan PostgreSQL untuk akun dan sesi. Tidak memerlukan IdP eksternal, Keycloak, OAuth/SSO, atau framework RBAC tambahan. Better Auth memverifikasi identitas dan sesi; aplikasi tetap menentukan peran, status akun, jalur jaringan dan kewenangan perangkat. Login dan verifikasi sesi hanya tersedia jika NetBird, DNS, HTTPS dan layanan lokal dapat dijangkau; tidak dijamin saat ISP putus.

- HTTPS tepercaya melalui domain privat NetBird untuk semua peran. Caddy satu-satunya ingress; firewall host menolak LAN tanpa VPN dan akses publik. DB dan port backend tidak dipublikasikan. Uji DNS, sertifikat, renewal dan akses dari peer berizin/tidak berizin.
- Semua request ke server wajib melalui jalur NetBird yang diizinkan. Jangan mempercayai header asal dari klien. Kasir memerlukan peran kasir, akun aktif, sesi sah dan perangkat kasir terdaftar yang sedang aktif. Direktur tetap memerlukan akun, sesi dan perangkat terdaftar. VPN bukan pengganti izin bisnis. Tidak ada bypass LAN; VPN saja tidak membuktikan lokasi fisik kasir.
- Usulan registrasi: direktur mengotorisasi perangkat baru; tautkan kredensial acak per perangkat melalui pendaftaran sekali pakai yang kedaluwarsa; simpan hanya digest di server dan cookie aman pada perangkat. Bukan fingerprint browser, alamat IP, atau ID yang diisi pengguna. Perlindungan ini tidak menjamin perangkat fisik tak dapat dikloning; lindungi perangkat operasional, jangan bagikan profil browser. Penyiapan direktur pertama memakai akses fisik PC yang diserahkan ke kafe. Pergantian perangkat kasir mematikan otorisasi lama dan dicatat dalam satu transaksi. Petugas yang membantu instalasi NetBird tidak otomatis memperoleh peran direktur.
  `POST /devices/register` hanya untuk direktur bersesi; `POST /devices/enroll` menukar undangan pada perangkat tujuan tanpa memerlukan cookie perangkat yang belum terbit. Validasi origin dan batasi percobaan; token hanya untuk jenis perangkat yang diundang. Penukaran tidak mengaktifkan perangkat kasir, tidak menerbitkan sesi kasir/direktur, dan tidak membuka akses laporan.
- Kata sandi akun per petugas dikelola Better Auth melalui autentikasi username/password melalui plugin resmi username. Field email internal yang diperlukan library dibuat secara unik oleh server, tanpa ketergantungan layanan email eksternal; login email langsung tidak dipublikasikan. Gunakan scrypt bawaan Better Auth; tidak perlu implementasi hashing khusus. Gunakan password sesuai batas bawaan Better Auth atau kebijakan yang disetujui dan jangan mewajibkan OTP atau verifikasi email eksternal. Tanpa default password tetap. Nonaktifkan pendaftaran publik; pembuatan akun hanya melalui prosedur direktur yang berwenang dan bootstrap lokal yang sudah ditentukan. Aktifkan rate limiting Better Auth dan pembatasan wrapper login melalui `@fastify/rate-limit` agar pemanggilan API server tidak melewati pembatasan; batasi juga percobaan reset dan enrollment di server, termasuk melalui VPN. Gunakan pesan generik dan hanya percaya alamat klien dari proxy tepercaya.
- Gunakan sesi opaque Better Auth berbasis PostgreSQL, bukan JWT stateless; nonaktifkan `session.cookieCache` agar pencabutan sesi segera berlaku. Verifikasi sesi dengan `auth.api.getSession` langsung di backend Fastify pada setiap request terlindungi; gagal tertutup jika autentikasi tidak tersedia, kemudian periksa ulang status akun, peran, jalur jaringan dan kredensial perangkat dari sumber tepercaya. Cookie sesi `HttpOnly`, `Secure`, `SameSite`, cakupan host/path minimum tanpa berbagi lintas subdomain. Rotasi sesi saat login; atur idle/absolute timeout sesuai shift sebelum operasional (batas absolut harus ditegakkan terpisah bila refresh sesi memperpanjang expiry). Gunakan skema sesi standar Better Auth tanpa adapter digest khusus. Token sesi pada database adalah rahasia yang harus dilindungi dengan pembatasan akses DB, backup dan log. Ini merupakan penyederhanaan terhadap usulan digest-only sebelumnya, untuk persetujuan Phase 1. Kredensial perangkat tetap disimpan sebagai digest terpisah.
- Terapkan pemeriksaan jalur jaringan, status akun dan perangkat sebelum penerbitan cookie sesi melalui handler/hook autentikasi server; seluruh jalur penerbitan sesi wajib tunduk pada aturan yang sama, termasuk pemanggilan API Better Auth secara langsung. Batasi endpoint autentikasi yang tidak diperlukan, termasuk perubahan identitas atau reset mandiri yang tidak sesuai prosedur. Tetapkan `baseURL` dan `trustedOrigins` eksplisit untuk origin HTTPS yang sah; jangan menonaktifkan pemeriksaan origin/CSRF Better Auth. Untuk endpoint mutasi aplikasi berbasis cookie, tetap wajib validasi origin dan CSRF token; jangan gunakan GET untuk mutasi. Izin offline lokal terpisah dari sesi API, mengikuti bagian berikut.
- Logout melalui Better Auth mengakhiri sesi itu saja; perangkat direktur lain tetap aktif. Saat akun dicabut atau password direset, cabut seluruh sesi akun terdampak di server melalui mekanisme Better Auth; pencabutan perangkat juga menghapus sesi perangkat dan harus langsung memblokir akses. Setiap request mencocokkan `session.device_id` dengan kredensial perangkat aktual. Setelah restore, hapus sesi dan undangan yang dipulihkan serta rekonsiliasi akun/perangkat sebelum membuka akses, sesuai `database.md`. Petugas baru menggunakan akunnya sendiri, tidak mengambil identitas transaksi lama. Direktur dapat mereset akun petugas; untuk direktur terakhir, usulan prosedur lokal di PC dengan verifikasi penanggung jawab kafe, set kata sandi baru dan cabut sesi lama, catat audit tanpa menyimpan rahasia. Reset login NetBird terpisah. Pemegang akses pemulihan perlu disepakati sebelum serah terima; tidak bergantung pada akun pribadi pengembang.

## Otorisasi dan integritas

- Sesi Better Auth bukan bukti kewenangan bisnis. Peran dan status akun hanya dapat diubah melalui operasi administratif server yang berwenang; jangan menerima nilai tersebut dari input profil atau payload klien. Default deny di handler dan operasi bisnis. Bedakan izin membuat SKU dengan harga awal dari mengubah harga lama; blokir perubahan field terlarang meskipun satu endpoint mendukung kedua peran. Hanya direktur boleh ubah tarif/zona/durasi, status produk, pengaturan akses, verifikasi tanggal dan baca laporan penuh/CSV. Direktur tidak menginput penjualan kasir. Batasi pencarian ID transaksi/nota dan kasus untuk kasir pada data yang diperlukan saat pencocokan; audit akses/perubahan penting, bukan setiap render.
- Gunakan schema request eksplisit: Zod strict pada frontend dan API Fastify; ukuran payload dibatasi, field tidak dikenal/terlarang ditolak. Validasi frontend hanya untuk kenyamanan pengguna. Validasi jumlah, metode tunggal, nominal integer, referensi, status dan transisi, keputusan tanggal serta jumlah pengembalian di server. Ambil identitas penginput dari sesi, bukan body. Untuk nota, simpan kasir asal secara terpisah; asal tidak terbukti adalah kasus, bukan alasan berpura-pura sebagai akun lama. Teks nota dan alasan selalu di-escape saat tampil. Gunakan query berparameter dan constraint PostgreSQL (UNIQUE, CHECK, NOT NULL, FOREIGN KEY) sesuai aturan bisnis; lindungi sel teks CSV dari formula spreadsheet dan kutip kolom dengan benar.
- ID percobaan dan nomor nota adalah alat rekonsiliasi, bukan credential. Simpan receipt dan efek bisnis secara atomik. Replay identik tidak mengulang efek; duplikat berbeda tidak menimpa penjualan; jangan mengembalikan data transaksi jika peminta tidak berhak. Sesudah timeout periksa ID asal. Jangan menganggap pencarian kosong dari server hasil restore sebagai bukti transaksi belum terjadi.
- Saat input susulan, kasir aktif boleh mencari identitas minimum petugas asal (termasuk nonaktif) tanpa mendapat daftar akun administratif. `link` dan penyelesaian nota selisih tidak mengubah aktor asal, tidak memberi kasir hak verifikasi direktur, dan tetap diaudit. `needs_check` pada meja bukan metadata bebas edit: server hanya melepas penanda setelah pemeriksaan yang cocok. Mengubah asosiasi tarif meja sama sensitifnya dengan mengubah tarif.
- QRIS diterima saat gangguan melalui pemeriksaan manusia dan transaksi lokal (nota jika penyimpanan gagal), bukan verifikasi bank atau unggahan bukti. Pemeriksaan foto bukan verifikasi bank. Catat rujukan minimum bila ada; tanpa nomor rekening lengkap atau salinan gambar di API, audit, backup, ataupun browser. Perbedaan bukti, tanggal dan pengembalian ditinjau tanpa menimpa data asal. Frasa bukti mirip/rujukan berulang memerlukan pencocokan manusia, bukan jaminan identitas pembayaran.

## Izin offline dan batas kepercayaan IndexedDB

- **Izin perangkat, bukan sesi petugas:** maksimal 7 hari dari penerbitan online oleh server. Direktur mengizinkan petugas; masing-masing login online dengan akun sendiri pada perangkat tersebut dan menyiapkan PIN pribadi sebelum dipakai offline. PIN hanya membuka identitas lokal yang tercantum dalam grant, bukan login Better Auth, MFA, credential API atau izin membuka laporan. Tidak ada akun baru, pendaftaran/reset PIN, penambahan petugas, atau perpanjangan grant secara offline.
- Simpan verifier PIN menggunakan KDF standar ber-salt unik per persiapan, bukan PIN polos atau hash cepat. Batasi percobaan gagal dan simpan pembatasannya agar reload tidak meresetnya. Jangan tampilkan/log/kirim PIN atau verifier; lindungi profil OS dan disk. Petugas keluar, PIN salah atau perangkat restart: layar terkunci. PIN benar hanya membuka satu petugas, tanpa mengakses sesi online petugas sebelumnya. Saat `now >= expires_at` atau umur izin tidak dapat dipercaya, hentikan transaksi baru; antrean tetap aman dari penghapusan oleh logout/kedaluwarsa. Pencabutan yang terjadi saat offline tidak bisa diketahui seketika; validasi per petugas saat sinkron, tahan kasus meragukan, jangan hapus transaksi.
- Izin lokal bukan jaminan kriptografis terhadap pengguna yang menguasai perangkat. IndexedDB dan jam perangkat dapat dimodifikasi; pencabutan akun tidak langsung diketahui saat offline. Batasi perangkat fisik/profil browser, waktu izin dan operasi (penjualan/rental saja); bila waktu meragukan, tahan operasi terkait. Direktur tidak memiliki akses offline ke laporan. Server memeriksa ulang Better Auth, status perangkat dan grant, snapshot dan aturan bisnis ketika sync; akun/perangkat dicabut atau asal meragukan masuk pemeriksaan manual, bukan bypass login.
- Tidak perlu custom enkripsi/token signing untuk baseline; gunakan proteksi OS, disk dan profil browser sesuai perangkat. Minta Storage Persistence, pantau quota, jangan clear site data; persistensi bukan backup. Jangan kirim data lokal ke telemetry. Saat storage gagal, jangan menyatakan transaksi tersimpan. Batasi akses data pending ke petugas berwenang; jangan hapus pending ketika logout/revoke/update.
- Sinkronisasi selalu via HTTPS/NetBird dengan sesi online dan CSRF sah. Server tidak percaya timestamp, role, total atau identitas dari klien; validasi Zod, snapshot historis dan aturan domain. ID stabil, sequence dan receipt menjaga idempotensi, bukan kredensial. Perubahan master yang memengaruhi snapshot dan pergantian perangkat diblokir saat grant terbuka hingga close/recovery; jika perangkat hilang, cabut akses server segera dan selesaikan secara manual sebelum mengaktifkan pengganti.


## Data, rahasia, dan operasi

- Terapkan security headers melalui `@fastify/helmet` dan Caddy dengan kebijakan yang tidak bertentangan: CSP yang kompatibel dengan PWA (hindari `unsafe-eval` di produksi), `X-Content-Type-Options: nosniff`, `Referrer-Policy` dan pembatasan framing. Aktifkan HSTS setelah HTTPS dan pemulihan sertifikat teruji. Jangan merender HTML mentah dari input pengguna.
- Gunakan Pino bawaan Fastify dengan redaksi cookie, authorization, password dan token; tidak perlu service logging tambahan. Batasi akses dan rotasi log. Jalankan `pnpm audit` sebelum rilis; tinjau temuan yang relevan, jangan meng-upgrade secara membabi buta.

- Service Worker hanya cache aset/shell publik; API, laporan, CSV dan respons privat network-only/no-store. IndexedDB terpisah menyimpan snapshot dan transaksi kasir minimum; tidak menyimpan password, cookie sesi, token API, foto QRIS atau laporan direktur. Logout bersihkan tampilan dan context aktif, tetapi jangan hapus antrean yang belum terselesaikan. Nota kertas cadangan jika PWA tidak dapat digunakan.
- Simpan password DB, `BETTER_AUTH_SECRET`, material TLS, credential backup dan recovery di konfigurasi terlindungi OS, bukan source, bundle frontend, URL atau log. Batasi akun OS dan peran DB aplikasi; pisahkan kewenangan migrasi/backup. Jangan beri hak mengubah/menghapus riwayat audit pada akun runtime. Lindungi PC, perangkat kasir dan media backup dari akses fisik tanpa izin; enkripsi media backup dan simpan kunci pemulihan terpisah sesuai SOP kafe. Disk/arsip terenkripsi tidak membantu jika kunci hanya ada di PC yang rusak.
- Batasi akses fisik nota dan foto QRIS pada petugas yang ditunjuk. Tetapkan tempat, masa simpan, dan pemusnahan aman. CSV yang telah diunduh berada di luar kontrol sesi web; beri label periode dan simpan hanya di perangkat direktur yang terkendali. Tentukan retensi backup bersama pemilik, bukan hardcode dalam aplikasi.
- Kunci versi dependency minimum yang memang dipilih, termasuk Better Auth; verifikasi migrasi skema autentikasi terhadap `database.md` dan konfigurasi endpoint terhadap `stack.md`; tinjau perubahan lockfile, lisensi dan advisory saat build/upgrade. Jangan menyalin token/session atau data kafe ke fixture, telemetry, atau layanan eksternal. Catat kegagalan akses penting, perubahan hak, pergantian perangkat, koreksi, refund dan verifikasi dengan aktor,waktu serta alasan; jangan catat password, secret, atau seluruh request. Tidak memerlukan SIEM/WAF publik untuk baseline satu lokasi ini.

## Pengujian yang diwajibkan, belum dijalankan

| Batas yang diuji | Skenario penolakan dan bukti positif |
|---|---|
| VPN, HTTPS | Putuskan ISP; catat apakah tunnel/DNS/server masih dapat dijangkau. Jika tidak, uji operasi IndexedDB; nota bila penyimpanan/izin gagal. Tolak LAN tanpa VPN, peer tanpa izin dan perangkat tidak aktif. DB dan port backend tidak dapat diakses langsung oleh klien. |
| Better Auth dan akses login | Uji login sah melalui VPN dan gagal tertutup saat auth tidak tersedia; tolak pendaftaran publik, akun nonaktif, login tanpa VPN, perangkat tidak aktif, percobaan berulang, origin asing, serta pemanggilan endpoint autentikasi langsung yang mencoba melewati pemeriksaan aplikasi. Periksa atribut cookie, pembatasan akses tabel sesi dan tidak adanya token pada log. |
| Sesi dan role | Dua perangkat direktur: logout satu, lainnya tetap sah. Tolak cookie sesi lama segera setelah pencabutan akun/perangkat atau reset password; uji idle/absolute timeout dan reset yang tak berwenang, mutasi tanpa proteksi CSRF, serta perubahan harga/status/ekspor oleh kasir. Uji backend langsung, bukan hanya menu. |
| Validasi dan keamanan request | Tolak field tambahan, nominal salah, payload berlebih, input XSS/SQL injection dan origin asing; pastikan constraint DB, header keamanan dan rate limiting berfungsi. |
| Kerahasiaan | Buka kembali PWA tanpa server dan setelah logout; tidak ada transaksi atau laporan privat di shell/cache; pending IndexedDB tetap ada tetapi tidak ditampilkan setelah logout. Foto QRIS dan rahasia tidak muncul di DB aplikasi, respons atau log. Uji ekspor dengan nama barang menyerupai formula. |
| Integritas uang dan stok | Dua pengiriman bersamaan, nomor nota sama isi berbeda, ID lama milik aktor yang tidak berhak, hasil simpan tidak diketahui, nota QRIS hanya bertanggal dan refund parsial berulang. Verifikasi uang, stok, meja, pembukuan dan audit secara terpisah. |
| Offline dan sync | Uji izin habis, logout/reload, manipulasi payload/jam, revoke saat offline, dua tab, quota penuh, respons hilang, restore dan retry; tidak ada bypass API, efek ganda, atau penghapusan pending. |
| Recovery | Simulasikan penggantian server dan perangkat; backup dapat dibuka petugas berwenang tanpa pengembang, akun/perangkat lama yang sempat dicabut tidak aktif kembali. Uji nota yang dapat dan tidak dapat dibuktikan; tidak membuat omzet untuk selisih tak terbukti. |

Referensi validasi: [Zod](https://zod.dev/), [OWASP ASVS](https://owasp.org/www-project-application-security-verification-standard/).

**Batas integrasi.** Fastify merupakan satu-satunya API aplikasi di balik Caddy. Better Auth adalah library server-only dalam proses yang sama, tanpa service terpisah. Wrapper `/api/v1/session` memanggil API server Better Auth dan mengembalikan cookie yang relevan; route mentah library tidak dipublikasikan. Terapkan pemeriksaan perangkat dan akun sebelum penerbitan cookie, dan cabut sesi yang terlanjur dibuat jika binding gagal. Jangan percaya identitas dari header klien. Uji provisioning/reset melalui API library resmi, bukan custom hashing atau penulisan token manual. Detail kontrak: `stack.md`.

Referensi implementasi Better Auth: [Username](https://better-auth.com/docs/plugins/username), [Security](https://better-auth.com/docs/reference/security), [Session Management](https://better-auth.com/docs/concepts/session-management), [Email & Password](https://better-auth.com/docs/authentication/email-password), [Database](https://better-auth.com/docs/concepts/database). Gunakan dokumentasi sesuai versi yang dikunci.

Pemilik: direktur untuk akses/backup dan serah terima; kasir untuk penjagaan nota selama gangguan dan pencocokan; penyedia untuk pembuktian konfigurasi di lokasi. Tanpa hasil uji, tidak ada klaim keamanan atau kesiapan operasional.
