# CerdikPOS — Keamanan dan bukti penerimaan

Status: rancangan kontrol hasil validasi 1.3, menunggu persetujuan Phase 1. Bukan laporan vulnerability, hasil pentest, atau bukti implementasi. Hak peran: [requirement.md](requirement.md); endpoint: [stack.md](stack.md); persistensi: [database.md](database.md).

## Aset dan batas kepercayaan

Lindungi transaksi, kas, bukti pemeriksaan QRIS, saldo dan histori stok, sesi meja, nota fisik, identitas petugas, ekspor dan backup. Pemisah utama: perangkat kasir vs server, jaringan tamu/LAN kasir vs jalur direktur NetBird, aplikasi vs PostgreSQL, nota fisik vs input digital. Keanggotaan VPN, alamat yang diklaim klien, tombol tersembunyi, atau kepemilikan nomor nota bukan bukti kewenangan.

## Akses jaringan, akun, dan sesi

- HTTPS tepercaya dengan hostname yang tetap dapat di-resolve di LAN tanpa ISP. Uji sertifikat, trust dan pembaruan sebelum serah terima. Jangan membuka API atau PostgreSQL ke internet; DB hanya dapat diakses komponen server yang memerlukannya. Batasi akses dari Wi-Fi tamu. Satu jalur privat direktur cukup; NetBird pada perangkat kasir untuk pendaftaran tidak memberi hak kasir remote.
- Saat login, menulis online atau mengirim antrean normal, server mensyaratkan jalur LAN, akun/peran kasir, perangkat aktif dan sesi sah. Bedakan LAN dan VPN pada interface/listener atau proxy tepercaya; jangan mempercayai header klien. Tolak kasir lewat VPN. Direktur tetap memakai perangkat terdaftar dan sesi sendiri. Selama server mati, izin kasir yang sebelumnya diberikan hanya mengizinkan pencatatan lokal terbatas; tidak membuka API atau membuktikan bahwa akses masih aktif di server.
- Usulan registrasi: direktur mengotorisasi perangkat baru; tautkan kredensial acak per perangkat melalui pendaftaran sekali pakai yang kedaluwarsa; simpan hanya digest di server dan cookie aman pada perangkat. Bukan fingerprint browser, alamat IP, atau ID yang diisi pengguna. Perlindungan ini tidak menjamin perangkat fisik tak dapat dikloning; lindungi perangkat operasional, jangan bagikan profil browser. Penyiapan direktur pertama memakai akses fisik PC yang diserahkan ke kafe. Pergantian perangkat kasir mematikan otorisasi lama dan dicatat dalam satu transaksi. Petugas yang membantu instalasi NetBird tidak otomatis memperoleh peran direktur.
  `POST /devices/register` hanya untuk direktur bersesi; `POST /devices/enroll` menukar undangan pada perangkat tujuan tanpa memerlukan cookie perangkat yang belum terbit. Validasi origin dan batasi percobaan; token hanya untuk jenis perangkat yang diundang. Penukaran tidak mengaktifkan perangkat kasir, tidak menerbitkan sesi kasir/direktur, dan tidak membuka akses laporan.
- Login online dan otorisasi perangkat mengikuti [referensi keamanan utama](../cerdikpos-offline-first_UPDATE/security.md). Direktur menentukan petugas; masing-masing login online pada perangkat aktif dan menyiapkan PIN pribadi. Izin perangkat berlaku maksimal 7 hari sejak diterbitkan server. PIN hanya membuka identitas lokal petugas yang telah disiapkan, bukan sesi API, login direktur atau pengganti password online. Tidak ada pendaftaran, reset PIN atau perpanjangan izin saat offline.
- Batasi percobaan PIN; simpan verifier ber-salt, bukan PIN asli. Logout, Ganti kasir atau restart mengunci layar pada semua tab tanpa menghapus antrean. PIN gagal tidak mengaktifkan petugas lama; blokir penjualan baru bila izin habis atau masa berlaku tidak bisa dipastikan. Sinkron hanya lewat sesi online yang sah, dengan pengirim dan kasir asal terpisah. Pencabutan tidak diketahui seketika saat offline; tahan data meragukan untuk pemeriksaan saat server kembali.
- Logout mengakhiri sesi itu saja; perangkat direktur lain tetap aktif. Saat akun dicabut atau password direset, cabut sesi terdampak di server. Petugas baru menggunakan akunnya sendiri, tidak mengambil identitas transaksi lama. Direktur dapat mereset akun petugas; untuk direktur terakhir, usulan prosedur lokal di PC dengan verifikasi penanggung jawab kafe, set kata sandi baru dan cabut sesi lama, catat audit tanpa menyimpan rahasia. Reset login NetBird terpisah. Pemegang akses pemulihan perlu disepakati sebelum serah terima; tidak bergantung pada akun pribadi pengembang.

## Otorisasi dan integritas

- Default deny di handler dan operasi bisnis. Bedakan izin membuat SKU dengan harga awal dari mengubah harga lama; blokir perubahan field terlarang meskipun satu endpoint mendukung kedua peran. Hanya direktur boleh ubah tarif/zona/durasi, status produk, pengaturan akses, verifikasi tanggal dan baca laporan penuh/CSV. Direktur tidak menginput penjualan kasir. Batasi pencarian ID transaksi/nota dan kasus untuk kasir pada data yang diperlukan saat pencocokan; audit akses/perubahan penting, bukan setiap render.
- Schema request eksplisit, ukuran payload dibatasi, field tidak dikenal/terlarang ditolak. Validasi jumlah, metode tunggal, nominal integer, referensi, status dan transisi, keputusan tanggal serta jumlah pengembalian di server. Ambil identitas penginput dari sesi, bukan body. Untuk nota, simpan kasir asal secara terpisah; asal tidak terbukti adalah kasus, bukan alasan berpura-pura sebagai akun lama. Teks nota dan alasan selalu di-escape saat tampil. Gunakan query berparameter; lindungi sel teks CSV dari formula spreadsheet dan kutip kolom dengan benar.
- ID percobaan dan nomor nota adalah alat rekonsiliasi, bukan credential. Simpan receipt dan efek bisnis secara atomik. Replay identik tidak mengulang efek; duplikat berbeda tidak menimpa penjualan; jangan mengembalikan data transaksi jika peminta tidak berhak. Sesudah timeout periksa ID asal. Jangan menganggap pencarian kosong dari server hasil restore sebagai bukti transaksi belum terjadi.
- Saat input susulan, kasir aktif boleh mencari identitas minimum petugas asal (termasuk nonaktif) tanpa mendapat daftar akun administratif. `link` dan penyelesaian nota selisih tidak mengubah aktor asal, tidak memberi kasir hak verifikasi direktur, dan tetap diaudit. `needs_check` pada meja bukan metadata bebas edit: server hanya melepas penanda setelah pemeriksaan yang cocok. Mengubah asosiasi tarif meja sama sensitifnya dengan mengubah tarif.
- QRIS saat server mati: kasir memeriksa bukti pelanggan dan mencatat hasil pemeriksaan di PWA; transaksi lokal bukan verifikasi bank. Gunakan nota hanya bila PWA gagal. Simpan nominal, tanggal, jam bila ada serta rujukan minimum tanpa foto atau nomor rekening lengkap. Verifikasi tanggal oleh direktur tetap online. Bukti/rujukan mirip memerlukan pencocokan, bukan menimpa pembayaran lain.

## Data, rahasia, dan operasi

- Cache Service Worker hanya berisi shell/aset; respons privat API, laporan dan CSV memakai `no-store`. Bedakan cache HTTP dari IndexedDB: yang terakhir menyimpan minimum data kerja dan event pembayaran tunai/sewa/QRIS pada perangkat kasir, bukan laporan direktur atau foto. Jangan simpan password atau cookie sesi di localStorage/IndexedDB. Batasi UI ke identitas berwenang; logout membersihkan tampilan privat dan memblokir penjualan baru tanpa menghapus data belum terkirim. Profil OS/browser khusus, kunci layar dan proteksi disk penting: akses fisik ke profil browser dapat membuka data lokal.
- Ekspor darurat hanya berisi antrean dan metadata asal, bukan sesi login. Gunakan enkripsi terautentikasi standar, derivasi kunci dari frasa sandi dan format arsip berversi; simpan media dan frasa terpisah. Pemulihan memerlukan login online di perangkat aktif, validasi format/asal/izin dan deduplikasi. Arsip atau izin lokal bukan otorisasi mutasi server; transaksi perangkat lama yang belum terbukti masuk pemeriksaan. Tetapkan pemegang akses ekspor saat sesi habis sebelum uji lokasi.
- Simpan password DB, material TLS, credential backup dan recovery di konfigurasi terlindungi OS, bukan source, bundle frontend, URL atau log. Batasi akun OS dan peran DB aplikasi; pisahkan kewenangan migrasi/backup. Jangan beri hak mengubah/menghapus riwayat audit pada akun runtime. Lindungi PC, perangkat kasir dan media backup dari akses fisik tanpa izin; enkripsi media backup dan simpan kunci pemulihan terpisah sesuai SOP kafe. Disk/arsip terenkripsi tidak membantu jika kunci hanya ada di PC yang rusak.
- Batasi akses fisik nota dan foto QRIS pada petugas yang ditunjuk. Tetapkan tempat, masa simpan, dan pemusnahan aman. CSV yang telah diunduh berada di luar kontrol sesi web; beri label periode dan simpan hanya di perangkat direktur yang terkendali. Tentukan retensi backup bersama pemilik, bukan hardcode dalam aplikasi.
- Kunci versi dependency minimum yang memang dipilih; tinjau perubahan lockfile, lisensi dan advisory saat build/upgrade. Jangan menyalin token/session atau data kafe ke fixture, telemetry, atau layanan eksternal. Catat kegagalan akses penting, perubahan hak, pergantian perangkat, koreksi, refund dan verifikasi dengan aktor,waktu serta alasan; jangan catat password, secret, atau seluruh request. Tidak memerlukan SIEM/WAF publik untuk baseline satu lokasi ini.

## Pengujian yang diwajibkan, belum dijalankan

| Batas yang diuji | Skenario penolakan dan bukti positif |
|---|---|
| LAN, VPN, HTTPS | Putuskan ISP; LAN tetap dapat menyimpan. Kasir pada jalur remote dan perangkat tidak aktif ditolak walau password benar. Direktur terdaftar bisa masuk via NetBird, DB tidak dapat diakses langsung dari perangkat klien. |
| Sesi dan role | Dua perangkat direktur: logout satu, lainnya tetap sah. Tolak cookie sesi lama, reset yang tak berwenang, mutasi tanpa proteksi CSRF, serta perubahan harga/status/ekspor oleh kasir. Uji backend langsung, bukan hanya menu. |
| Kerahasiaan | Buka kembali PWA tanpa server dan setelah logout; tidak ada transaksi atau laporan privat di shell/cache. Foto QRIS dan rahasia tidak muncul di DB aplikasi, respons atau log. Uji ekspor dengan nama barang menyerupai formula. |
| Integritas uang dan stok | Dua pengiriman bersamaan, nomor nota sama isi berbeda, ID lama milik aktor yang tidak berhak, hasil simpan tidak diketahui, nota QRIS hanya bertanggal dan refund parsial berulang. Verifikasi uang, stok, meja, pembukuan dan audit secara terpisah. |
| Recovery | Simulasikan penggantian server dan perangkat; backup dapat dibuka petugas berwenang tanpa pengembang, akun/perangkat lama yang sempat dicabut tidak aktif kembali. Uji nota yang dapat dan tidak dapat dibuktikan; tidak membuat omzet untuk selisih tak terbukti. |
| Offline opsi B | Uji akun dicabut saat terputus, kedaluwarsa/clock rollback, kehilangan perangkat, penolakan mutasi master, dan kegagalan tulis. Bukti lama tidak terhapus; tanpa hak sah tidak ada transaksi baru. Coba replay event QRIS dan arsip yang sama; satu pembayaran tanpa foto dan tanpa efek stok/sewa tambahan. |

Pemilik: direktur untuk akses/backup dan serah terima; kasir untuk penjagaan nota selama gangguan dan pencocokan; penyedia untuk pembuktian konfigurasi di lokasi. Tanpa hasil uji, tidak ada klaim keamanan atau kesiapan operasional.
